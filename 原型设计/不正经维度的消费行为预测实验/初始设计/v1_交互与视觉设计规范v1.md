# 「聊聊你喜欢的事」交互与视觉设计规范 v1

对应内部项目：不正经维度的消费行为预测实验 · 首轮（闲聊维度）
设计依据见[初始设计文档](设计文档.md)。

---

## 1. 这份设计要解决什么

一场实验是两个人坐在一起完成的：主持人带着聊，受访者放松地说，然后受访者对 10 件商品表态。页面要做到三件事。

1. **主持人不看说明也能带完全程。** 每一屏只做一件事，下一步永远只有一个主按钮。
2. **受访者表态时不受任何预测信息影响。** 这是实验成立的前提，页面要从结构上保证，而不是靠主持人自觉。
3. **对照结果一眼能读。** 负责人最想知道的是「10 件里猜中几件，猜错的错在哪」。

不做的事：账号登录、多人管理后台、数据看板、动效装饰、画像可视化图谱。这些都超出首轮要验证的问题。

## 2. 使用场景假设

| 项目 | 假设 | 说明 |
| --- | --- | --- |
| 设备 | 一台笔记本或平板，两人同看一块屏 | 字号和点击区按「隔一臂距离也能看清」设计 |
| 操作者 | 闲聊阶段主持人操作，表态阶段把屏幕交给受访者 | 两个阶段的界面语气不同，见第 5 节 |
| 闲聊记录 | 主持人把整理好的闲聊文字粘贴或录入 | 首轮不做页面内录音转写 |
| 一场时长 | 闲聊 10–15 分钟，表态 2–3 分钟 | 表态环节要快，靠直觉 |

如果实际是远程两块屏，流程不变，只需把「交屏」改成「发链接」，这一点请确认。

## 3. 三档态度的措辞

**题干**：单看这件东西本身，先不管价格，你想要它吗？

| 档位 | 按钮文字 | 辅助说明 | 记录值 |
| --- | --- | --- | --- |
| 正向 | 想要 | 有的话会开心 | +1 |
| 中性 | 无感 | 有没有都行 | 0 |
| 负向 | 不想要 | 送我也不太想留 | −1 |

几点取舍理由：

- **不用「厌恶」「讨厌」。** 它比「想要」强一个量级，三档会不对称，受访者也不好意思点，结果会挤到「无感」。
- **「不想要」和「无感」靠辅助说明拉开。** 无感是有没有都行，不想要是给了也不想留。
- **题干先把价格拿掉。** 首轮要看的是「想不想要」，不是「买不买得起」。闲聊里没有收入信息，把价格混进来等于让模型猜一个它没有线索的东西。
- **对照用记录值算差。** 分差 = 预测值 − 本人值，结果为 0 是一致，±1 是差一档，±2 是方向相反。这与设计文档的「分差取预测分减本人分」一致。

## 4. 流程与分屏

全程五屏，线性推进，顶部有一条五步进度。

```
① 开场  →  ② 闲聊记录  →  ③ 过渡  →  ④ 商品表态  →  ⑤ 完成与对照
主持人      主持人          两人        受访者         主持人 / 负责人
```

### ① 开场

- 内容：标题「聊聊你喜欢的事」、设计文档里的邀请语、一句参与说明（系统会根据闲聊猜你对几件东西的态度，之后和你自己的选择对照）。
- 测试编号自动生成，小字显示在页面角落，不需要主持人填。
- 主按钮：开始聊。

### ② 闲聊记录

- 左栏是四个话题提示卡：日常和家庭、电影和小说、游戏和爱好、成长经历。每张卡上是设计文档里的问法，主持人照着顺口问即可。聊过的可以点一下标记，纯粹帮主持人记进度，不入库。
- 右栏是一个大文本框，放「送入预测的闲聊文字」，下方显示字数。
- 文本框上方有一条固定的边界提醒：提交前请略去收入、职业、消费观念、购买记录、买或不买某件东西的理由。
- 主按钮：提交闲聊记录。点击后弹确认框，重申「提交后不能再改，预测将只使用这段文字」。
- 这一屏不出现任何商品信息。

### ③ 过渡

- 提交瞬间后台做两件事：封存这段文字，发起预测任务。
- 屏幕上是一句话：「聊得很开心，谢谢你。接下来给你看 10 件东西，凭第一感觉选就好。」加一小段三档说明。
- **不强制等待模型。** 设计文档的流程是预测和表态并行，受访者不需要干等。过渡屏本身就是一次自然的停顿，主持人在这里把屏幕交给受访者。
- 主按钮：开始看。

### ④ 商品表态

- 一屏一件。居中一张商品卡：图、名称、一句中性的资料说明。下方三个大按钮。
- 选完自动进入下一件，停顿约 0.4 秒让受访者看到自己选了什么。可以返回上一件改。
- 顶部显示「第 3 件 / 共 10 件」和 10 个小圆点，圆点只表示答没答，不显示选了什么颜色，避免受访者去凑分布。
- 第 10 件之后进入一览：10 件缩略排成两行，每件标出已选档位，点任意一件可改。有缺项时该件高亮并提示「还差第 X 件」，主按钮置灰。
- 主按钮：提交我的选择。提交后不能再改。
- **这一屏不出现预测状态、预测结果、画像、进度百分比中的任何一项。**

### ⑤ 完成与对照

- 先给受访者一个完成反馈：「已经记下了，谢谢你。」
- 下方一个次级入口「查看对照（主持人）」。点了才展开，默认收起。是否让受访者一起看，由主持人现场决定。
- 如果此时预测还没回来，对照区显示「模型还在猜，稍等一下」；预测失败时显示「这次没猜出来」和「按原材料重试」按钮，本人选择不受影响。
- 对照区内容，从上到下：
  1. 一句结论：10 件里猜中 X 件。旁边小字给参照线：三档随机猜大约中 3 件。
  2. 三个计数：一致、差一档、方向相反。
  3. 逐件对照表：商品、本人选择、模型预测、差异。
  4. 可展开的「模型眼里的这个人」，即模型生成的简要画像，默认收起。
  5. 页脚小字：测试编号、闲聊封存时间、预测完成时间、本人提交时间、模型配置与提示词版本。

## 5. 上下文隔离怎么落到界面上

| 隔离要求 | 界面与流程上的做法 |
| --- | --- |
| 模型不知道受访者怎么选 | 预测请求在闲聊提交时发出，内容在那一刻封存。受访者的选择存在另一份记录里，不回传给预测任务，重试也只用原材料。 |
| 模型不知道后面有对照环节 | 送给模型的只有闲聊文字、商品资料、三档规则。 |
| 受访者不知道模型怎么猜 | 表态屏没有任何预测相关元素。对照区要在本人提交之后，由主持人主动点开。 |
| 闲聊不被商品带偏 | 商品在闲聊提交之后才第一次出现。 |
| 事后可查证 | 对照区页脚并列三个时间戳，能看出预测材料封存早于本人表态。 |

## 6. 两种界面语气

同一套视觉，靠三处细节区分「主持人在操作」和「受访者在操作」。

| | 主持人屏（①②⑤对照区） | 受访者屏（③④⑤完成反馈） |
| --- | --- | --- |
| 信息密度 | 可以有提示条、字数、编号 | 一屏一件事，没有辅助信息 |
| 文案 | 直接、操作性：「提交前请略去…」 | 口语、轻松：「凭第一感觉选就好」 |
| 标识 | 页面角落有「主持人」小标签和测试编号 | 不显示标签和编号 |

## 7. 视觉规范

整体感觉：像一本安静的笔记本，暖、淡、留白多。屏幕上最鲜明的颜色只留给三档按钮和对照结果。

### 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F7F4EE` | 暖米白，比纯白放松 |
| 卡片背景 | `#FFFFFF` | |
| 主文字 | `#23262B` | |
| 次文字 | `#6B7078` | |
| 分割线、描边 | `#E6E1D8` | |
| 主操作色 | `#2F5D50` | 深墨绿，用于主按钮和进度；悬停 `#264C42` |
| 主持人提示条 | 底 `#FBF3E4` 字 `#7A5A1E` | 只在主持人屏出现 |
| 想要 | `#D9763C` | 暖橙 |
| 无感 | `#8C9198` | 中性灰 |
| 不想要 | `#4F6D8F` | 灰蓝 |
| 一致 | `#2F7D5B` | |
| 差一档 | `#C4912B` | |
| 方向相反 | `#B5523F` | |

三档态度不用红绿。红绿带着「对错」「好坏」的暗示，会让受访者觉得「不想要」是个不礼貌的答案。暖橙对灰蓝是一冷一暖，没有褒贬。表示对错的颜色只在对照区出现。

### 字体与字号

- 字体：系统默认中文无衬线（苹方、微软雅黑），不加载外部字体。
- 屏幕标题 32px 半粗；商品名 28px 半粗；正文 18px；辅助说明 15px；页脚信息 13px。
- 行高 1.6。受访者屏的正文每行不超过 24 个汉字。

### 版式与组件

- 内容区最大宽度 960px，居中。受访者屏内容区收窄到 640px。
- 卡片圆角 16px，1px 描边，不加阴影或只加极浅阴影。
- 主按钮高 52px，圆角 12px。每屏只有一个主按钮，固定在内容区底部右侧。
- 三档按钮：等宽并排，高 88px，上面是档位名（22px），下面是辅助说明（14px）。未选时白底加对应色描边，选中后填充对应色、白字。
- 顶部进度：五个步骤名加一条细线，当前步骤用主操作色，其余为次文字色。
- 商品图：4:3，圆角 12px。首轮没有定稿图片时用浅色底加品类图标占位。

### 动效

只有两处：切屏时 200ms 淡入；选中三档按钮后 400ms 再切下一件。其他地方不动。

## 8. 状态与异常

| 情况 | 页面表现 |
| --- | --- |
| 闲聊文字为空或过短 | 主按钮置灰，文本框下提示「再多记一点，至少 100 字」。阈值待定。 |
| 表态有缺项 | 一览里高亮缺的那件，提示还差第几件，补齐才能提交。 |
| 中途刷新或误关 | 回到刷新前那一屏，已提交的闲聊和已选的档位都在，测试编号不变。 |
| 重复点击提交 | 按钮点击后立即锁定，同一测试编号只记一次。 |
| 预测超时或结果无效 | 只在对照区告知，提供「按原材料重试」。受访者流程不受影响。 |
| 预测先于本人完成 | 结果只存不显示，等本人提交后才可查看。 |

## 9. 待你确认的三件事

1. **三档措辞和题干**是否按第 3 节定。尤其「先不管价格」这个前提，它决定了我们测的是想要还是购买意向。
2. **首批 10 件商品**。原型里放的是示例占位，品牌、图片、资料说明都需要你定。
3. **对照结果给不给受访者看。** 现在的设计是默认收起、主持人现场决定。如果你想固定为「不给看」或「一定给看」，流程可以更简单。

另有两处是我按设计文档做的选择，和你口头说的略有出入，请留意：

- 口头说的是「聊完等一下模型处理」，设计文档是预测和表态并行。我采用了并行，不让受访者干等。
- 设计文档写的是「打分」「量表」，口头说的是三档态度。本规范统一按三档。
